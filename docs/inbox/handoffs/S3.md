## Što je S2 ostavio (e2e prošao 19. 11. 2026., odluke 200–206)

- Produkcija prima: Resend domena `poruke.logomedo.com` (samo primanje), MX i DKIM u Cloudflareu, webhook
  `email.received`, `RESEND_WEBHOOK_SECRET`. Resend API ključ: `~/.config/logomedo/secrets.env` (chmod 600;
  `set -a; . ~/.config/logomedo/secrets.env; set +a`).
- U produkcijskoj D1 je **razgovor 1** (testni Gmail korisnika, `domovinasync@…`): odlazna pozivnica (id 1) i dolazni
  odgovor (id 2) s dva privitka u R2 (`poruke/<email_id>/…`, PNG i PDF). Koristi ga za e2e odgovora iz admina.
- **Niti (odluka 206):** `GET /emails/{resend_id}` odlazne poruke vraća `message_id`
  (`<…@eu-west-1.amazonses.com>`), a Gmailov odgovor ima točno taj `In-Reply-To` i u `References`. Za odgovor iz
  admina: nakon `POST /emails` dohvati `GET /emails/{id}`, spremi `message_id` u `poruke.message_id`, a slanje
  postavlja `In-Reply-To` = `message_id` zadnje dolazne i `References` = njezine reference + taj id. Pozivnica još
  ne sprema svoj `message_id` (S3 to može dodati istim dohvatom).
- **Privitci:** Gmail je oba obična privitka poslao s `content_id`, pa `content_id` **ne znači** ugrađenu sliku.
  U niti prikaži sve privitke kao popis; kao ugrađene tretiraj samo one čiji se `cid:` stvarno pojavljuje u HTML-u.
- Upit za provjeru (stupac je `status`, nema `nerasporedjen`):
  `SELECT r.id, r.status, r.neprocitano, p.smjer, p.in_reply_to IS NOT NULL, (SELECT COUNT(*) FROM privitci x WHERE x.poruka_id=p.id) FROM razgovori r JOIN poruke p ON p.razgovor_id=r.id`
