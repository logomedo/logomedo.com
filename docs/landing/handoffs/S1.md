# S1: staging okruženje

Polazni commit: 26e55c6 (`main`). `npm test && npm run check && npm run build`: 276 testova (pass 276, skipped 0), check 0 grešaka, build prolazi. Odluke od **100**.

Korisnik je 19. 11. 2026. odobrio staging na `staging.logomedo.com` s kopijom produkcijske D1. To
uključuje stvaranje novih Cloudflare resursa (Worker, D1, R2, queue, custom domain u zoni
logomedo.com) i **čitanje** produkcijske D1 (`wrangler d1 export --remote`). Ništa produkcijsko se
ne mijenja.

Paket:

1. **Mjerenje adaptera (prije ikakve izmjene).** Spremi `dist/server/wrangler.json` trenutnog
   builda kao referencu (`npm run build`, kopija u scratchpad). Pogledaj
   `node_modules/@astrojs/cloudflare/dist/utils/wrangler-config.js` (čita `CLOUDFLARE_ENV`) i
   `@cloudflare/vite-plugin`: kako se bira okruženje, što ide u `dist/server/wrangler.json`
   (`topLevelName`, `definedEnvironments`), može li staging build ići u zaseban `outDir` da
   paralelni produkcijski `npm run deploy` ne pokupi staging konfiguraciju (preporuka: `dist-staging/`,
   dodati u `.gitignore`). Gdje adapter postavlja `assets` i može li se za staging uključiti
   `run_worker_first` (potrebno za odluku 7: Basic Auth i na statičkim datotekama). Zapis:
   `docs/landing/research/2026-11-19-astro-cloudflare-okruzenja.md`.
2. **`env.staging` u `wrangler.jsonc`.** Vrhnja (produkcijska) konfiguracija ostaje bajt-za-bajt
   ista. U `env.staging`: `name` `logomedo-staging`; `routes` samo
   `{ "pattern": "staging.logomedo.com", "custom_domain": true }`; `workers_dev` i `preview_urls`
   false; `d1_databases` (`DB` → `logomedo-staging`, isti `migrations_dir`); `r2_buckets`
   (`SLIKE` → `logomedo-staging-slike`, `JAVNO` → `logomedo-staging-javno`); `queues` producer i
   consumer `logomedo-staging-zvukovi`; `durable_objects` + `migrations` za `RunnerZvono`; `vars`:
   `ADMIN_HOST` `staging.logomedo.com`, `CDN_URL` `https://cdn.logomedo.com` (odluka 6),
   `ZONE_ID` isti, `ACCESS_TEAM_DOMAIN` isti, `ACCESS_AUD` prazan (pa `/admin/sso` vraća 503),
   `OKRUZENJE` `staging`; `observability` kao produkcija. Bindingi se u wrangler okruženjima ne
   nasljeđuju, pa sve mora biti navedeno. `wrangler types` ako se `Env` mijenja (`OKRUZENJE`).
3. **Skripte u `package.json`:** `build:staging`, `deploy:staging` (s
   `CLOUDFLARE_ACCOUNT_ID=7dc7167b7e2e00923bfa7cd697df14e4`, vidi zamku u `docs/admin.md`),
   `db:migrate:staging`. Postojeće skripte se ne mijenjaju.
4. **Dokaz da je produkcija ista:** `npm run build` i `diff` novog `dist/server/wrangler.json` s
   referencom iz koraka 1 mora biti prazan (ili samo polja koja ne utječu na deploy, svako
   objašnjeno u zapisu iz koraka 1). Bez ovoga ne ide dalje.
5. **Zaštita staginga (odluka 7)** u `src/middleware.ts` / `src/worker.ts`: kad je
   `env.OKRUZENJE === "staging"`, svaki zahtjev osim `/api/v1*` i `/api/runner/*` traži Basic Auth
   (korisnik proizvoljan, lozinka = secret `STAGING_LOZINKA`, usporedba u konstantnom vremenu);
   bez nje 401 s `WWW-Authenticate`. Bez postavljenog secreta na stagingu: 503, nikad otvoreno.
   Svim odgovorima staginga `x-robots-tag: noindex`. Ako se statičke datoteke ne mogu provući
   kroz Worker (korak 1), zapiši posljedicu i najbolju zamjenu kao odluku. Testovi (`node --test`):
   bez `OKRUZENJE` ponašanje isto kao danas; sa `staging` 401/200/503 i izuzeci.
6. **Resursi i secret:** `wrangler d1 create logomedo-staging` (upiši `database_id`),
   `wrangler r2 bucket create` za oba bucketa, `wrangler queues create logomedo-staging-zvukovi`,
   `npm run db:migrate:staging`, `wrangler secret put STAGING_LOZINKA --env staging` (lozinka
   nasumična, spremljena u `.env.staging` koji je gitignored; provjeri `.gitignore`).
   Ako wrangler OAuth odbije R2 ili custom domain zbog ovlasti, stani i pitaj korisnika
   (preporuka: `wrangler login` s potrebnim ovlastima).
7. **Kopija produkcije (odluka 5):** `scripts/staging-osvjezi.sh`: `wrangler d1 export logomedo
   --remote --output ~/.cache/logomedo-staging/prod-<datum>.sql` (prije pokretanja provjeri u
   Cloudflare dokumentaciji blokira li export produkcijsku bazu i koliko; izmjereno trajanje upiši
   u research zapis), zatim isprazni staging D1 i importaj dump (`wrangler d1 execute
   logomedo-staging --remote --env staging --file …`), pa obriši dump. Skripta na kraju ispiše broj
   redaka ključnih tablica (`rijeci`, `slike`, korisnici/sesije prema shemi) za staging i
   produkciju (čitanje). Sesije i passkeyevi iz produkcije na stagingu ne rade (rpID), to je u redu.
8. **Admin na stagingu (odluka 8):** `scripts/staging-sesija.sh <email>` upisuje sesiju u staging
   D1 (po uzoru na „Lokalno” u `docs/admin.md`) i ispisuje vrijednost kolačića; e-mail je
   argument, nikad u repou.
9. **Deploy i e2e:** `npm run deploy:staging`. Provjera s `curl`: `/` bez lozinke 401, s lozinkom
   200 i `x-robots-tag: noindex`; statička datoteka (npr. `/favicon.svg`) bez lozinke 401 (ili
   zapisana iznimka iz koraka 5); `/admin` s kolačićem iz koraka 8 200; `/api/v1` bez tokena 401 od
   vlastite provjere. `wrangler deployments list` (produkcija) i dalje pokazuje istu zadnju verziju
   kao prije sesije.
10. **`docs/staging.md`**: što je staging, deploy, osvježavanje podataka, prijava, što ne radi
    (kandidati slika, izgovor, runner, passkey s produkcije), kako dodati Access kasnije.
    Kratka poveznica iz `CLAUDE.md` repoa.
